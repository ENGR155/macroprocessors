# Proposal working draft: Hall-sensed magnetic levitator

**Readiness:** an implementation proposal for team review, not an already validated promise. First confirm the feasible object and gap interval; then replace candidate numerical specifications with the team’s committed values and paginate the prose to the course limit. Supporting diagrams, calculations, schedule, and BOM are linked below.

We will build a single-axis magnetic suspension using the E155 STM32L432KC and UPduino v3.1. An overhead electromagnet will support an object containing a permanent magnet. Two linear Hall sensors and a measured coil-current signal will estimate its vertical gap. A local Wi-Fi webpage will select a bounded gap target, show estimated gap/current/fault status, and stop operation. A capped current-test mode will support calibration and debugging while the object is mechanically supported.

The proposed acceptance specification is continuous suspension for 30 seconds, operation at three commanded gaps in a validated interval initially targeted at 8–14 mm, steady mean gap error no greater than 0.5 mm after settling, and recovery from a small recorded disturbance. A current cap, loss-of-command timeout, and physical interlock will remove drive when required. A separate reference measurement will evaluate actual height; the Hall estimate alone will not establish accuracy. Feasibility testing may require a narrower interval before this proposal is committed.

The MCU will perform calibrated field compensation, filtered velocity estimation, 1 kHz PD/PID position control, target ramping, UART communication with the course ESP8266, and 1 MHz SPI exchanges with the FPGA. The FPGA will acquire current and both Hall channels through an MCP3204, run a fixed-point 10 kHz PI current controller, generate 20 kHz PWM, validate commands, and apply autonomous fault/watchdog supervision. These functions continue while the MCU formats and transmits pages.

The largest technical risk is separating object position from coil field across changing current, temperature, and object orientation. We will test this first using known gaps and currents, then validate a local estimator on an independent sweep. If the estimator cannot meet the proposed error bound, the geometry/object/sensor arrangement must change before claiming a working height loop. A steel-only sphere requires explicit current-dependent characterization and is not assumed compatible with the initial estimator.

The power circuit uses a separately supplied coil, low-side MOSFET and gate driver, an inline current shunt/amplifier inside the flyback loop, and a physical E-stop/current comparator interlock. Coil force across an air gap, current response, and continuous heating will determine final component ratings. Default firmware and HDL are disabled until bring-up gates pass.
