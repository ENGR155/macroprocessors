MCU Design

Position estimation, control, and communication on the STM32L432KC.

Overview

The STM32L432KC estimates the gap between the object and the coil and calculates the current needed to reach the target gap. It also communicates with the FPGA over SPI and the ESP8266 over UART.

Control Update

The board driver configures a nominal 16 MHz HSI clock, 1 MHz SPI1, 125000-baud USART1, a 1 MHz TIM2 timestamp, and a 1 ms SysTick. Each control update exchanges a 16-byte packet with the FPGA.

The update has four main steps:

  1. Send the previous current request and receive the sensor readings. Check the checksum, fault bits, and sample ID.
  2. Convert the sensor readings to current and gap using the configured scaling and calibration. Calculate and filter the downward velocity.
  3. Update the target gap and calculate the next current request.
  4. Handle webpage requests and transmit the response over UART without blocking the next control update.

Position Controller

The current request is calculated using the gap error, filtered velocity, and an integral term:

error = measured_gap - ramped_target
current_request = clamp(
    hover_current + Kp*error + Kd*filtered_velocity + integral,
    0, maximum_current
)

The derivative term uses the measured velocity so that changing the target does not cause a derivative kick. The integral updates only when the current request is within its limits or the error would bring it back within those limits.

The default gains and hover current are zero. We still need to measure the sensor scaling, fit the gap model, and tune the gains. The current-test mode uses a separate current ramp with the object supported.

Webpage Interface

We use the existing ESP8266 firmware from the course. The MCU sends the HTML over UART and handles the returned commands. The interface includes height and current-test modes, arm, clear, and stop controls, and sensor readings. If the browser stops renewing its five-second lease, the controller stops the output.

This website documents the project. The hardware control page is served separately by the MCU and ESP8266.

Timing and Fault Handling

A missed update, invalid telemetry, stalled sample ID, or reported fault stops the coil. At 1 MHz, a 128-clock SPI exchange with chip-select guards takes at least 132 microseconds before software delays. The estimated worst-case delay from measurement to output is roughly 2-3 ms, including ADC scanning, scheduling, SPI transfer, and PWM updates.

We still need to measure these delays on hardware. Formatting and sending the webpage also need to fit around the control updates.

Testing

The October 15 verification record reports passing host-side behavior tests and Cortex-M4F compilation of all seven C source files. The full GNU Arm executable link and board programming have not been verified. Compiling the source files alone does not confirm that the firmware can be flashed and run.
